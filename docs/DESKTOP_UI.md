# 단타 관리 화면 v0.1 (2026-10-13)

기준 커밋: d2509ac. Python/Tkinter 로컬 데스크톱 화면입니다.
브라우저·서버·추가 계좌 인증 없이 기존 설정과 로그를 사용합니다.
**창을 여는 것만으로 자동매매가 시작되지는 않습니다.**

## 실행

저장소 루트의 `start_desktop.bat`을 더블클릭합니다. 기존 `.venv`가 필요합니다.
터미널에서 기존 가상환경을 활성화했다면 다음 명령도 가능합니다.

```powershell
python -m app.desktop
```

Windows 공식 Python 설치의 Tcl/Tk 구성요소가 필요합니다. `_tkinter` 오류가 나면
Python 설치 관리자의 Modify에서 Tcl/Tk and IDLE을 설치합니다.
기존 `.env`, config/settings.yaml, 가상환경을 그대로 쓰며 설정 파일을 덮어쓰지 않습니다.
이 버전은 독립 exe 패키지가 아닙니다.

## 사용

- 자동매매 시작: 실제 현재 설정의 Mock/모의/실전을 확인하고 시작합니다.
  별도 자식 프로세스에서 기존 `python -m app.main`을 실행합니다.
  상태의 '프로세스 실행 중'은 인증 완료나 매매 준비 완료를 뜻하지 않습니다.
  실제 초기화 성공 여부는 매매/실행 로그에서 확인합니다.
- 정상 종료: 종료 요청을 기록하고 현재 순회/통신이 끝나기를 기다립니다.
  진행 중인 주문 요청을 강제 취소하거나 프로세스를 kill하지 않습니다.
  요청 후 현재 순회가 끝나기 전에는 다른 종목 주문이 이어질 수 있습니다.
  장전/폴링 대기는 약 0.25초 간격으로 종료 요청을 확인합니다.
  초기 인증·동기 API 지연 중에는 더 기다릴 수 있으며 종료 시간을 보장하지 않습니다.
- 종료는 전량 매도나 미체결 취소가 아닙니다. 종료 후 자동 감시는 멈춥니다.
  확인 창에서 실제 보유·미체결은 키움에서 확인하도록 안내합니다.
- 창 닫기: GUI에서 시작한 프로세스가 실행 중이면 종료를 요청한 후 실제 프로세스
  종료까지 창을 유지합니다. ZIP 생성 중에도 완료 전 창을 닫지 않습니다.
- 이전 창 실행 종료 요청: GUI가 비정상 종료된 경우 이 저장소의 GUI 실행 기록에
  종료 요청을 보냅니다. 기록 개수는 살아있는 프로세스 수가 아니며 종료 여부는
  로그로 확인해야 합니다. 수동 터미널 실행을 종료하거나 PID를 강제 종료하지 않습니다.
- 기존 엔진의 상태 파일 OS 잠금으로 GUI/터미널 간 중복 매매 실행을 차단합니다.
  같은 저장소 GUI 창도 별도 OS 잠금으로 한 개만 엽니다.
  다른 상태 파일/다른 복제 폴더를 사용하는 프로그램까지 전역 차단하지는 않습니다.
- 보고서 폴더: 기존 reports 폴더를 엽니다.
- 분석 ZIP 내보내기: 입력 날짜로 기존 export_daily_bundle.py를 실행합니다.
  결과는 `exports/bundle_YYYYMMDD.zip`; 실패 이유는 실행/내보내기 로그에 표시합니다.

## 표시 데이터의 의미

날짜 기본값은 창을 연 날(한국 시간)이고 바뀐 날짜를 조회하려면 입력값을 변경합니다.
화면 갱신은 약 2초 주기이며 파일 수정 시각을 별도로 표시합니다.
실제 계좌 잔고나 실시간 시세를 GUI에서 추가 조회하지 않습니다.

- 주문 내역: 조회일 마지막 200개 CSV 기록입니다. 접수 성공을 체결 확정으로 표시하지 않습니다.
- 추정 손익: 기존 analyze_trades의 동일 날짜·동일 수량 1:1 주문가격 쌍과 공통
  cost_model Base 비용을 사용합니다. 이월/부분체결 손익·계좌 실현손익이 아닙니다.
- 큰 파일: 거래 CSV 16MiB 초과 시 손익 집계를 생략하고 확인 불가로 표시합니다.
  신호 CSV는 4MiB 초과 시 최근 부분만 읽으며 전체 일일 건수가 아님을 표시합니다.
- 파일 없음/손상/작성 중인 불완전 행은 경고를 표시합니다. 읽기 실패를 0원으로 처리하지 않습니다.
- 로컬 미해결 주문 의도는 state.json의 기록이며 실제 계좌 미체결 건수나 보유 수가 아닙니다.
- 실행 상태는 이 창이 소유한 자식 프로세스 기준입니다. 외부 실행 여부는 단정하지 않습니다.
- 로그 화면은 최근 64KiB를 표시하며 기존 번들 마스킹 함수를 사용합니다.
  로그 원본 파일 자체를 이 GUI가 마스킹해서 다시 쓰지는 않습니다.

## 변경 파일과 검증

`app/desktop.py`: 화면, `desktop_model.py`: 파일 조회/프로세스 제어,
`desktop_control.py`: 협조적 종료, `start_desktop.bat`: Windows 실행기.
`app/main.py`에는 종료 요청 확인과 기존 대기 구간 연결만 추가합니다.
신호·손절·주문금액·설정 YAML·기존 상태 파일 스키마를 변경하지 않습니다.

새 `test_desktop_dashboard.py`는 실제 주문/브로커 로그인 없이 실행합니다.
장전 종료, 처리 중 순회 완료 후 종료, CLI 대기 호환, 중복 실행, 이전 GUI 실행 복구,
ZIP 날짜 검증, 한국 날짜 경계, 불완전/대용량/빈 CSV, 비용 기준과 로그 마스킹을 검증합니다.

```powershell
python test_desktop_dashboard.py
python run_regression_tests.py
```

기존 실패: test_broker_order_status.py(원본 fixture 누락),
test_order_status_evidence_observation.py(기존 상태 관련 assertion).
실제 Windows 창·키움 연결 상태의 시작/종료는 사용자 PC에서 최종 확인해야 합니다.
실전 주문을 통한 검증이나 원격 저장소 푸시는 수행하지 않습니다.
